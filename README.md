## W0.1 — identidade estável, unidades, vocabulário
- **`stable_id`**: toda entidade versionada tem `stable_id` compartilhado por todas as versões (v1: `id = stable_id`). `PATCH` cria nova linha com o mesmo `stable_id`.
  **Referências (`node_id`, `sku_id`, `origin_node_id`, `dest_node_id`, `sku_ids[]`) recebem o `stable_id`**, não o id da linha-versão — editar um nó não quebra capacity/rotas/vendas.
  A referência precisa ter versão corrente (nó aposentado → `400 invalid_reference`). No banco, FK composta `(tenant_id, stable_id)` → `nodes_identity`/`skus_identity` impede referência cross-tenant mesmo fora da API.
  `GET /api/<e>/:id/history` aceita id de qualquer versão ou o `stable_id`; `GET /api/<e>?stable_id=` filtra.
- **Unidades/moeda = `tenant_settings`** (`uom`, `currency`), nunca o nome do campo. Aliases da API (colunas SQL do contrato mantidas até a W0.2):

  | API (use este) | coluna SQL (legado) |
  |---|---|
  | `node_capacity.capacity_per_period` | `capacity_t_month` |
  | `routes.cost_per_unit` | `cost_per_ton` |

  Entrada aceita alias ou coluna legada (os dois com valores diferentes → `400 alias_conflict`); saída devolve **só o alias**. `GET /api/entities` lista os campos da API + mapa de aliases.
- **`node_type`**: validado contra `tenant_settings.node_types` quando a lista não está vazia (`400 invalid_node_type`). Lista vazia = qualquer texto não vazio.
  **`policies.kind`**: texto livre não vazio (tenant_settings ainda não tem lista de kinds; se entrar, validar igual ao `node_type`).

## Auth stub + tenancy
Headers por request: `x-tenant-id` (obrigatório) e `x-user-id` (obrigatório para escrita; vira `created_by`/`actor` no audit).
Cada request roda numa transação com `set_config('app.tenant_id', $1, true)`; o isolamento é do **RLS no Postgres**, não do filtro na app.
FKs são validadas sob RLS + FK composta `(tenant_id, stable_id)` no banco (não dá para referenciar `node_id`/`sku_id` de outro tenant).

## W2b — A7 stub (máquina de estados da decisão, `src/a7/decision.ts`)
Determinístico (sem LLM, sem rede; regra 5 do gate). Estado por (cenário, `scenarioVersion` corrente) = última decisão da versão:
`pending —approve→ approved` (fecha a versão) · `pending —escalate→ escalated —approve (só domain_owner)→ approved`. Nova versão do cenário volta a `pending`.
- **approve** exige `run_id` de run `done` (feasible|partial) do **mesmo** cenário e **não stale** (stale = `run.scenario_version ≠ versão corrente`, cenário `status=stale`, ou premissa criada/editada — `premise_cards.created_at`/`audit_log` — depois do início do run). Wire v0.3: "aprovar desabilitado se stale".
- **escalate**: run opcional (stale/failed ok; queued/running → 409). Wire: "Escalar continua possível".
- **why** (trim): sempre obrigatório (contrato `minLength 1` + CHECK no banco). **≥ 20** quando o run tem razão `warn`/`block` ou outcome `partial`. Só feasible sem warn/block aceita why curto (≥1) — "why opcional" **não** foi implementado: exigiria mudar o contrato (ver Gaps).
- `actor.role` vem do usuário do header (nunca do body). `users.role = admin` (seed) → `domain_owner` (enum do contrato não tem `admin`); `system` reservado p/ automação. `audit_log.actor_role` guarda o papel real.
- Concorrência: `pg_advisory_xact_lock` por cenário (2 aprovações simultâneas → a 2ª recebe `decision_closed`).

## W4 — Execution pulse write (Task 10, `src/execution/` + `src/http/execution.ts`)
Contrato: `docs/architecture/W4-EXECUTION-PULSE-WRITE-CONTRACT.md` (aprovado Deivid + PO). Determinístico, sem LLM/`fetch(`/prompt e sem DELETE (gate **regra 8**).
- **Cravos PO:** bucket = **dia** (`periodStart` date) · batch **all-or-nothing** (sem 207) · limiar **15% fixo** (`EXEC_THRESHOLD` em `src/execution/pulse.ts`).
- **Pulse:** movimentos `posted` do run do `planRef` (approved > latest_run) → buckets `(dia, kind, nó, SKU)`; `planned` = soma dos `qtyPlanned` não nulos. `planned>0 ∧ actual=0` → **block**; `|actual−planned|/planned > 0.15` → **warn**; `planned` nulo/0 → nada. `kind`: ship/receive/transfer → `janela`, produce → `capacidade`, other → `outro`; dedupe inclui o dia; `tags: ["unapproved_plan"]` quando basis ≠ approved. Exceções entram em `viol` (severityCounts).
- **Aderência** (`summary.execution.adherence`, Kpi `ratio`): `1 − Σ|a−p|/Σp` nos buckets com plano da janela de 7 dias até o último dia com movimento; sem dado → `null` + `no_plan|no_data` (nunca inventa). `pending.executionExceptions` = nº de buckets sinalizados.
- Concorrência: `pg_advisory_xact_lock(hashtextextended('execution:'||tenant,0))` em POST/batch/void. Audit: `create` por linha (com `batchIndex`) e `void` com `why`.
