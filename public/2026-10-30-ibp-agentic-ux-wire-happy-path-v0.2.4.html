    Regras de validação (UI deve impedir)
      
      
    • Ditado vazio → não chama o A1; erro no campo.
      • 
      
    • Gap sem nó current (links.nodeId null, linha-versão ou aposentado) → cartão inválido com linguagem invalid_reference (“nó current obrigatório”); “Gerar cenário” bloqueado.
      • 
      
    • Prontidão A4 = block → run não é criado; tela 4 mostra itens em falta com link pro Cadastro.
      • 
      
    • Run infactível → “Aprovar” desabilitado; só escalar. Run com razão warn/block ou factível parcial → aprovar exige porquê ≥ 20 caracteres.
      • 
      
    • Regra PO (porquê, Task 7) → porquê sempre não-vazio (≥ 1) ao aprovar e ao escalar. Factível limpo (reasons: []) aceita porquê curto; não há aprovação sem porquê.
      • 
      
    • Erro técnico → nada persistido; “Tentar de novo” repete o run na mesma versão do cenário.
      • 
      
    • Edição de premissa → version+1, source="edit"; se o cenário já existe, cria nova versão do cenário e invalida o run A4 anterior.
      • 
      
    • Run A4 em andamento → “Rodar de novo” e “Ver takeaways” travados; resultado de run cuja versão de cenário ficou velha é descartado.
      • 
      
    • Cockpit → máx. 3 cenários; o 4º exige arquivar um; o cenário em análise não pode ser arquivado.
      • 
      
    • Decisão (aprovar ou escalar) sem “porquê” → bloqueada; com porquê → evento no audit trail.
