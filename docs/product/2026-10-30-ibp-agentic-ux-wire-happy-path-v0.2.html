    PremiseCard
    {

    A4Reason
    {
  "rank": 1,                                   // int ≥ 1 (always-on mostra 1..3)
  "kind": "janela | tancagem | contrato | custo | outro",
  "summary": "CD3 excede tancagem em 18%…",    // pt-BR, 1 frase, ≤ 160 chars (UX)
  "refs": { "nodeId": "CD3", "skuId": null, "routeId": null, "period": "2027-06..2027-09" },
  "severity": "info | warn | block"            // canônico; legado: baixa→info, media→warn, alta→block
}
    • UI: info azul · warn âmbar · block vermelho. O badge mostra o valor do enum, sem tradução.
    • Rótulos de takeaway (escalar, na política, contexto) são do A7/UX — não são severity.
    A4RunSummary (always-on + countsByKind)
    {
  "runId": "RUN-A4-3181",
  "scenarioId": "SCN-0142",
  "reasons": [ /* A4Reason, maxItems 3, ordenado por rank */ ],
  "countsByKind": { "janela": 7, "tancagem": 12, "contrato": 3, "custo": 5, "outro": 1 }
                  // todas as 5 chaves sempre presentes (0 se vazio)
}
    • Drill-down SKU × rota × período = linhas do mesmo run (filtro por kind), não nova chamada ao solver.
    Regras de validação (UI deve impedir)
    • Ditado vazio → não chama o A1; erro no campo.
    • Gap sem links.nodeId → cartão inválido; “Gerar cenário” bloqueado.
    • Edição de premissa → version+1, source="edit"; se o cenário já existe, cria nova versão do cenário e invalida o run A4 anterior.
    • Run A4 em andamento → “Rodar de novo” e “Ver takeaways” travados; resultado de run cuja versão de cenário ficou velha é descartado.
    • Cockpit → máx. 3 cenários; o 4º exige arquivar um; o cenário em análise não pode ser arquivado.
    • Decisão (aprovar ou escalar) sem “porquê” → bloqueada; com porquê → evento no audit trail.
